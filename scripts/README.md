# Model Training Pipeline

These scripts document how the Mangekyo risk scoring model was built — from raw data collection through training and validation. They are not required to run the tool. The trained model (`model.pkl`) is distributed via the [GitHub Release](https://github.com/Marckevf/mangekyo-cli/releases/latest) and baked into the Docker image.

---

## Pipeline order

### Step 0 — Data collection (three sources)

**`0_collect_internetdb.py`**
Collects host data from Shodan InternetDB for a list of target IPs. Outputs raw port, CPE, and CVE data per host.

**`0_collect_censys_data.py`**
Collects host data from Censys for additional coverage and diversity. Supplements InternetDB with hosts that Shodan may not have indexed.

**`0_collect_diversity.py`**
Collects hosts specifically chosen for service diversity — different port profiles, OS types, and exposure levels. Ensures the training dataset isn't biased toward a single type of host.

The three collection scripts are independent and can be run in any order. Their outputs are combined into a single dataset before the next step.

---

### Step 1 — Ground truth generation (no script — baked into scoring engine)

Ground truth risk scores are generated by running the canonical four-signal formula directly against each collected host:

```
risk = (nvd_risk × 0.60) + (base_risk × 0.15) + (epss × 0.20) + (kev_bonus × 15.0)
```

This produces the labeled dataset the model trains on. The formula is the source of truth — the model learns to reproduce it.

---

### Step 2 — Feature matrix (no standalone script — part of training pipeline)

Raw host data is converted into a feature matrix by `src/mangekyo/feature_extractor.py`. The final feature matrix used for training is `final_feature_matrix.csv` (gitignored — large file, regenerable).

---

### Step 3 — Model training

**`3_train_model.py`**
Trains a Random Forest surrogate model on the feature matrix. Outputs `model.pkl` and a SHAP summary plot (`shap_summary.png`). The model learns to reproduce the ground truth formula with R² 0.9963 on real-on-real 5-fold cross validation across 17,113 rows.

---

### Step 4 — Validation

**`4_robustness_checks.py`**
Runs robustness checks on the trained model — out-of-distribution hosts, edge cases, confidence under data degradation. Confirms the model generalizes beyond the training distribution.

---

## Utility scripts

**`generate_synthetic_scans.py`**
Generates synthetic Nmap XML files for testing. Used to build the `xml_logs/synthetic/` directory (gitignored). Not part of the model training pipeline.

**`reconcile_feature_matrix.py`**
Reconciles the feature matrix against the raw collected data to catch label mismatches or missing rows.

**`retrain_validate.py`**
Combined retrain + validate in one pass. Used when updating the dataset and retraining the model.

**`run_three.py`**
Batch runner for the three data collection scripts.

**`auth_probe.py`**
Probes a target for authenticated services during data collection.

**`check_cves.py`**
Spot-checks CVE coverage for a given host against the NVD API. Used during data validation.

---

## Training data

Training CSVs (`training_data_v2.csv`, `final_feature_matrix.csv`, `metadata.csv`) are gitignored — they are large files that can be regenerated by running the pipeline. The 17,113-row dataset was collected from real internet-facing hosts across the three collection scripts above.
